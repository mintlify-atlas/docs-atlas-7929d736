## How to Contribute

### 1. Find Something to Work On

You can contribute by:

- Fixing bugs reported in [Issues](https://github.com/Netcracker/qubership-profiler-agent/issues)
- Adding new instrumentation plugins for libraries/frameworks
- Improving documentation
- Enhancing test coverage
- Optimizing performance

### 2. Fork and Clone

```bash
# Fork the repository on GitHub
# Then clone your fork
git clone https://github.com/YOUR_USERNAME/qubership-profiler-agent.git
cd qubership-profiler-agent

# Add upstream remote
git remote add upstream https://github.com/Netcracker/qubership-profiler-agent.git
```

### 3. Create a Branch

```bash
# Update your local main branch
git checkout main
git pull upstream main

# Create a feature branch
git checkout -b feature/my-new-feature
```

<Info>
  Use descriptive branch names like `feature/add-redis-plugin` or `fix/memory-leak-in-instrumenter`.
</Info>

### 4. Make Your Changes

- Follow the existing code style
- Add tests for new functionality
- Update documentation as needed
- Keep commits focused and atomic

### 5. Test Your Changes

```bash
# Run all tests
./gradlew build

# Run tests for specific module
./gradlew :plugins:myplugin:test

# Check code coverage
./gradlew jacocoReport
```

### 6. Commit Your Changes

Write clear, descriptive commit messages:

```bash
git add .
git commit -m "Add instrumentation plugin for Redis

- Implement RedisPlugin for Jedis client
- Add tests for connection tracking
- Document plugin configuration"
```

<Note>
  Follow the [Conventional Commits](https://www.conventionalcommits.org/) style when possible.
</Note>

### 7. Push and Create Pull Request

```bash
# Push to your fork
git push origin feature/my-new-feature
```

Then:
1. Go to the GitHub repository
2. Click "New Pull Request"
3. Select your branch
4. Fill out the pull request template
5. Submit for review

## Pull Request Guidelines

### PR Title

Use clear, descriptive titles:
- `Add Redis instrumentation plugin`
- `Fix memory leak in ClassEnhancer`
- `Update build documentation`

### PR Description

Include:

<AccordionGroup>
  <Accordion title="What changed">
    Describe the changes you made and why
  </Accordion>
  <Accordion title="How to test">
    Provide steps to verify the changes work
  </Accordion>
  <Accordion title="Related issues">
    Link to related issues using `Fixes #123` or `Relates to #456`
  </Accordion>
  <Accordion title="Checklist">
    - [ ] Tests added/updated
    - [ ] Documentation updated
    - [ ] CLA signed
    - [ ] Code follows project style
  </Accordion>
</AccordionGroup>

### Code Review Process

1. **Automated Checks**: CI builds and tests run automatically
2. **Maintainer Review**: Project maintainers review the code
3. **Feedback**: Address any requested changes
4. **Approval**: Once approved, maintainers will merge

## Coding Standards

### Java Code Style

- Use 4 spaces for indentation (not tabs)
- Follow Java naming conventions
- Keep methods focused and small
- Add Javadoc for public APIs
- Use meaningful variable names

### Plugin Development

- Follow the [Plugin Development Guide](/development/plugin-development)
- Name plugin classes as `EnhancerPlugin_<name>`
- Add comprehensive tests
- Document configuration options
- Include README.md in plugin directory

### Testing

- Write unit tests for new functionality
- Ensure tests are deterministic
- Use descriptive test names
- Aim for high code coverage

### Documentation

- Update relevant documentation
- Add code comments for complex logic
- Include examples where helpful
- Keep README files up to date

## Development Workflow

### Setting Up Development Environment

```bash
# Install Java 17 or 21
# Clone repository
git clone https://github.com/Netcracker/qubership-profiler-agent.git
cd qubership-profiler-agent

# Build project
./gradlew build

# Import into IDE (IntelliJ IDEA recommended)
```

### Running Tests

```bash
# All tests
./gradlew test

# Specific module
./gradlew :agent:test

# With coverage
./gradlew test jacocoReport
```

### Local Testing

Test your changes with a sample application:

```bash
# Build agent
./gradlew :agent:build

# Run with your application
java -javaagent:agent/build/libs/profiler-agent.jar \
     -jar your-app.jar
```

## Release Process

<Note>
  Only maintainers can create releases. This section is for informational purposes.
</Note>

Releases are managed through GitHub Actions:

1. Navigate to [Release Workflow](https://github.com/Netcracker/qubership-profiler-agent/actions/workflows/release.yaml)
2. Click "Run workflow"
3. Select branch and version
4. Workflow builds and publishes to Maven Central
5. Creates GitHub release with generated notes

The workflow:
- Checks that the release tag doesn't exist
- Updates version in `gradle.properties`
- Builds and publishes artifacts
- Creates release tag
- Bumps to next version
