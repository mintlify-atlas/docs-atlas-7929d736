This guide will help you attach the Qubership Profiler Agent to a JVM application and start collecting profiling data.

## Prerequisites

Before you begin, ensure you have:

- Java 17 or higher installed
- A Java application you want to profile
- The Qubership Profiler Agent distribution (see [Installation](/installation))

## Quick Start Steps

<Steps>
  <Step title="Download the agent">
    Download the latest Qubership Profiler Agent from the [GitHub releases page](https://github.com/Netcracker/qubership-profiler-agent/releases).
    
    Extract the distribution archive:
    
    ```bash
    unzip qubership-profiler-agent-3.1.6.zip -d /opt/qubership/profiler
    ```
  </Step>

  <Step title="Attach the agent to your JVM">
    Add the `-javaagent` flag to your Java application startup command:
    
    ```bash
    java -javaagent:/opt/qubership/profiler/lib/qubership-profiler-agent.jar \
         -jar your-application.jar
    ```
    
    <Tip>
      The agent automatically discovers and loads all instrumentation plugins from the `lib` directory.
    </Tip>
  </Step>

  <Step title="Configure the collector endpoint">
    Set environment variables to specify where profiling data should be sent:
    
    ```bash
    export REMOTE_DUMP_HOST=your-collector-host
    export REMOTE_DUMP_PORT_PLAIN=1715
    
    java -javaagent:/opt/qubership/profiler/lib/qubership-profiler-agent.jar \
         -jar your-application.jar
    ```
    
    <Note>
      If no remote collector is configured, the agent will store profiling data locally in the dump directory.
    </Note>
  </Step>

  <Step title="Verify the agent is running">
    Check your application logs for the profiler initialization message:
    
    ```
    Profiler: initialized, version 3.1.6
    ```
    
    You should also see connection information for the remote collector (if configured).
  </Step>
</Steps>

## Example: Profiling a Simple Application

Here's a complete example of running a Java application with the profiler agent:

<CodeGroup>

```bash Docker
docker run -e REMOTE_DUMP_HOST=collector.example.com \
           -e REMOTE_DUMP_PORT_PLAIN=1715 \
           -v /opt/qubership/profiler:/profiler \
           your-app-image \
           java -javaagent:/profiler/lib/qubership-profiler-agent.jar \
                -jar /app/application.jar
```

```bash Standalone
export PROFILER_HOME=/opt/qubership/profiler
export REMOTE_DUMP_HOST=collector.example.com
export REMOTE_DUMP_PORT_PLAIN=1715

java -javaagent:$PROFILER_HOME/lib/qubership-profiler-agent.jar \
     -jar /path/to/your-application.jar
```

```bash Kubernetes
apiVersion: v1
kind: Pod
metadata:
  name: profiled-app
spec:
  containers:
  - name: app
    image: your-app:latest
    env:
    - name: JAVA_OPTS
      value: "-javaagent:/profiler/lib/qubership-profiler-agent.jar"
    - name: REMOTE_DUMP_HOST
      value: "profiler-collector-service"
    - name: REMOTE_DUMP_PORT_PLAIN
      value: "1715"
    - name: CLOUD_NAMESPACE
      valueFrom:
        fieldRef:
          fieldPath: metadata.namespace
    - name: MICROSERVICE_NAME
      value: "my-service"
    volumeMounts:
    - name: profiler
      mountPath: /profiler
  volumes:
  - name: profiler
    hostPath:
      path: /opt/qubership/profiler
```

</CodeGroup>

## Configuration Options

The agent can be customized through configuration files and environment variables:

### Basic Configuration

The profiler home directory (`PROFILER_HOME`) contains:

```
/opt/qubership/profiler/
├── lib/                              # Agent and plugin JARs
│   ├── qubership-profiler-agent.jar
│   ├── qubership-profiler-boot.jar
│   ├── qubership-profiler-runtime.jar
│   └── qubership-profiler-*.jar      # Plugin JARs
└── config/                           # Configuration files
    ├── _config.xml                   # Main configuration
    └── logback.xml                   # Logging configuration
```

### Environment Variables

Key environment variables for profiler configuration:

| Variable | Description | Default |
|----------|-------------|---------|
| `REMOTE_DUMP_HOST` | Collector server hostname | (none) |
| `REMOTE_DUMP_PORT_PLAIN` | Plain TCP port for collector | `1715` |
| `REMOTE_DUMP_PORT_SSL` | SSL/TLS port for collector | (none) |
| `FORCE_LOCAL_DUMP` | Force local dump even with remote configured | `false` |
| `CLOUD_NAMESPACE` | Kubernetes namespace | Auto-detected |
| `MICROSERVICE_NAME` | Service name for identification | Auto-detected |

<Tip>
  For a complete list of configuration options, see the [Configuration Reference](/setup/configuration).
</Tip>

## Viewing Profiling Data

Profiling data can be accessed in several ways:

1. **Remote Collector**: Data is streamed in real-time to a collector service
2. **Local Files**: When no remote collector is configured, data is written to local dump files
3. **Web UI**: Use the included profiler UI to visualize traces and performance data

<Note>
  The profiler uses minimal overhead instrumentation and is designed for production use.
</Note>

## Getting Help

<Warning>
  If the agent fails to initialize, check that:
  - The agent JAR path is correct and accessible
  - Java 17+ is being used
  - The `lib` directory contains all required JARs
  - File permissions allow reading the agent files
</Warning>

For more help, see the [Troubleshooting Guide](/operations/troubleshooting) or [open an issue](https://github.com/Netcracker/qubership-profiler-agent/issues) on GitHub.
