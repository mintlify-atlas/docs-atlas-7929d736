The Qubership Profiler Agent provides instrumentation for a wide range of frameworks, libraries, and application servers through its plugin system.

## Plugin Architecture

Each plugin provides:
- **Bytecode instrumentation** - Automatic method interception
- **Performance tracking** - Call duration and frequency
- **Context propagation** - Distributed tracing support
- **Parameter capture** - Method arguments and return values

## Plugin Configuration

Plugins are automatically loaded based on detected libraries on the classpath. No explicit configuration is required in most cases.

### Enabling/Disabling Plugins

To control which plugins are active, use the agent configuration:

```xml
<profiler>
  <plugins>
    <plugin name="spring" enabled="true"/>
    <plugin name="mysql" enabled="true"/>
    <plugin name="cassandra" enabled="false"/>
  </plugins>
</profiler>
```

### Plugin Loading Priority

Plugins are loaded in this order:

1. **Core plugins** - HTTP, JDBC, basic instrumentation
2. **Framework plugins** - Spring, Jakarta EE
3. **Library plugins** - Third-party integrations

## Plugin Development

To create custom plugins:

1. Implement the `ProfilerPlugin` interface
2. Define instrumentation points using the plugin API
3. Package as a separate module under `plugins/`
4. Add to `settings.gradle.kts`

See the [Plugin Development Guide](/development/plugin-development) for details.
